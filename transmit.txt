신속하게 대응해 주셨네요! backend.py의 통신 속도(9600)와 명령어 형식을 최신화했으므로, 이제 FSW와 GCS 간의 '언어'가 일치하게 되었습니다.

실제 하드웨어를 연결하여 XBee 통신 테스트부터 시뮬레이션 테스트까지 진행하는 단계별 매뉴얼을 정리해 드립니다.

1. 하드웨어 연결 (XBee 및 Teensy)
XBee 설정 확인:

두 개의 XBee 모듈(송신용, 수신용)이 서로 같은 PAN ID와 **Baudrate(9600)**로 설정되어 있는지 XCTU 프로그램을 통해 확인하세요.

Teensy(FSW) 연결:

Teensy 4.1의 Serial2 핀(TX2: 8번, RX2: 7번)에 XBee 송신 모듈을 연결합니다.

Teensy에 전원을 공급(USB 또는 배터리)합니다.

지상국(GCS) 연결:

XBee 수신 모듈(USB 어댑터 포함)을 PC에 연결합니다.

장치 관리자에서 할당된 COM 포트 번호를 확인하고, backend.py의 SERIAL_PORT_NAME이 해당 포트(예: "COM45")와 일치하는지 확인합니다.

2. 소프트웨어 실행 및 기본 통신 테스트
GCS 실행:

터미널에서 python main.py를 실행합니다.

로그창(Echo Terminal)에 [GCS] 포트 연결 성공 메시지가 뜨는지 확인합니다.

CX ON (텔레메트리 시작):

GCS 화면의 CX ON 버튼을 클릭합니다.

FSW가 명령을 받으면 packetCount를 올리며 1초마다 데이터를 전송하기 시작합니다.

검증: GCS의 표(Table)와 차트(Chart)에 데이터가 실시간으로 찍히는지 확인하세요.

SET TIME (시간 맞추기):

SET TIME 버튼을 눌러 PC의 UTC 시간을 FSW로 전송합니다.

표의 MISSION_TIME이 00:00:00에서 현재 시간으로 바뀌어 카운트되는지 확인합니다.

3. 시뮬레이션 테스트 (가장 중요)
FSW가 실제 비행 중인지 착각하게 만들어 상태 전환(FSM)이 잘 일어나는지 확인하는 과정입니다.

시뮬레이션 모드 진입:

사이드바의 시뮬레이션 패널에서 ENABLE 버튼을 누릅니다. (FSW의 flightMode가 'S'로 변함)

이어서 ACTIVATE 버튼을 누릅니다.

기압 보정 (CAL):

시뮬레이션 데이터를 넣기 전, 반드시 CALIBRATE 버튼을 누르세요. 현재 기압을 지면 기압(groundPressure)으로 저장합니다.

데이터 주입 (상태 전환 확인):

GCS 시뮬레이션 입력창에 기압값(Pa)을 수동으로 입력하거나 준비된 시나리오 파일을 로드합니다.

상승 테스트: 기압을 점점 낮춥니다 (예: 101325 -> 90000). 고도가 올라가며 상태가 ASCENT로 변하는지 확인합니다.

방출 테스트: 최고점(APOGEE)을 찍은 후 기압을 다시 높입니다. 고도가 내려오며 PROBE_RELEASE 등의 이벤트와 함께 MEC 에코가 돌아오는지 확인합니다.

4. 문제 발생 시 체크리스트
데이터가 안 들어와요: XBee의 TX/RX 배선이 교차(Teensy TX -> XBee RX)되어 있는지, 보레이트가 둘 다 9600인지 재확인하세요.

고도가 0에서 안 변해요: CAL 명령을 먼저 보냈는지, 그리고 시뮬레이션 기압(SIMP) 값이 유효한 숫자인지 확인하세요.

명령어 에코가 없어요: FSW 소스코드에서 TEAM_ID가 GCS와 동일한 1062로 컴파일되어 있는지 확인하세요.
